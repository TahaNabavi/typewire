# query-core: cross-tab & offline seams

This release adds four **additive** hooks to the query engine — a fetch `gate`,
a `sources` resolver, an `updatedAt` on `setQueryData`, and a `reason` on the
`removed` cache event. Together they are everything a cross-tab **sync** adapter
and an **offline** replay adapter need to attach to the engine without forking
its pipeline.

Nothing here changes how the engine behaves on its own. With none of the options
set, every fetch, mutation, write and eviction is **byte-for-byte identical** to
before — which is the whole point of landing these ahead of the packages that
consume them.

## Why these four, and why now

`typewire-sync` mirrors one tab's cache into others; `typewire-offline` queues
writes and replays them when the network returns. Both were blocked on the same
missing seams, and the third design law forbids either from wrapping or
re-implementing the engine. So the seams land **once, here, first**:

- a mirror must **single-flight** a fetch across tabs, and **lock** a write
  behind a queue — that is the `gate`;
- an inbound mirror must turn an id back into an endpoint to write it through the
  typed API — that is `sources`;
- an adopted value must keep the **origin's** timestamp, not the moment it
  arrived — that is `updatedAt`;
- a mirror must tell a local eviction from a deliberate removal — that is
  `reason`.

## The fetch gate

`gate` wraps every fetch and every mutation the client runs. The engine hands it
a `run` thunk and awaits whatever it returns, so a gate can run the request and
pass its result through, or resolve **without** calling `run` and hand back a
value obtained elsewhere.

```ts
const client = new QueryClient({
  gate: (ctx, run) => {
    // ctx: { key, endpointId, input, kind: "query" | "mutation" }
    return run() // the default — unchanged behaviour
  },
})
```

Semantics:

- **wraps the retry loop, not one attempt** — a gate that runs the request still
  sees every retry, and a single-flight loser that adopts the winner's result
  gets the _settled_ value.
- **`kind`** separates a `"query"` fetch from a `"mutation"`, so a gate can
  single-flight reads and serialise writes with different logic.
- **`key`** is the cache key (`endpointId|hash(input)`) — the same key two tabs
  compute for the same call, which is what makes cross-tab single-flight
  possible.
- resolving without calling `run` means **the endpoint is never invoked**: the
  losing tab adopts a broadcast result rather than issuing its own request.

## `sources`

`sources` resolves a cross-package id back to the endpoint carrying it — either a
function or a prebuilt map. `collectSources` builds the map by walking a client's
`.modules` tree and keying every leaf by its `endpointId` / `eventId`.

```ts
import { collectSources } from '@tahanabavi/typefetch-query-core'

const client = new QueryClient({
  sources: collectSources(api.modules, socket.modules),
})

client.resolveSource('user.getUser') // the generated endpoint, or undefined
```

The inbound half of sync needs this: a mirrored write arrives as an id and a
value, and must find the endpoint to write through the typed `setQueryData` —
**including for an endpoint this tab has not mounted yet**. Passing more specific
clients last lets them win an id collision.

## `setQueryData(..., { updatedAt })`

`setQueryData` (and the underlying `query.setData`) accept an optional
`{ updatedAt }` that seeds `dataUpdatedAt` with an explicit time instead of
`Date.now()`.

```ts
client.setQueryData(endpoint, input, value, { updatedAt: origin.timestamp })
```

A value mirrored from another tab must carry the **origin's** timestamp.
Restamping it "now" would make every mirror look fresher than the data it copied,
so a newer real value would lose a last-writer-wins comparison. Omitted, the
timestamp is `Date.now()` exactly as before.

## `reason` on the `removed` event

The `removed` cache event now carries `reason: "gc" | "explicit"`.

```ts
client.subscribe((event) => {
  if (event.type === 'removed' && event.reason === 'explicit') {
    // propagate; a "gc" eviction is local bookkeeping only
  }
})
```

A garbage-collection eviction after `gcTime` is local bookkeeping; a
`removeQueries` / `clear` is intent the user expressed. Nothing downstream could
tell them apart before this field, and a mirror must — it should broadcast the
explicit removal and ignore the eviction.

## API additions

| Export                                    | Kind     | Purpose                                                   |
| ----------------------------------------- | -------- | --------------------------------------------------------- |
| `FetchGate`                               | type     | Wraps a fetch/mutation: `(ctx, run) => Promise<unknown>`. |
| `GateContext`                             | type     | `{ key, endpointId, input, kind }` handed to the gate.    |
| `SourceResolver`                          | type     | `endpointId → source`, as a function or a map.            |
| `collectSources(...trees)`                | function | Build a `SourceResolver` map from `.modules` trees.       |
| `QueryClientOptions.gate`                 | field    | Register the gate on a client.                            |
| `QueryClientOptions.sources`              | field    | Register the source resolver on a client.                 |
| `client.resolveSource(id)`                | method   | Resolve an id via `sources`; `undefined` if unknown.      |
| `setQueryData(..., { updatedAt })`        | arg      | Preserve an explicit write timestamp.                     |
| `query.setData(updater, { updatedAt })`   | arg      | Same, on the query directly.                              |
| `QueryCacheEvent` `removed.reason`        | field    | `"gc"` vs `"explicit"`.                                   |
| `QueryCache` constructor `gate`           | arg      | Threaded from the client; internal.                       |
| `QueryConfig.gate` / `MutationHooks.gate` | field    | Threaded to query/mutation; internal.                     |

## Backward compatibility

- `gate` and `sources` are opt-in. With neither set, fetch and mutation paths run
  unchanged and add no work; `resolveSource` returns `undefined`.
- `setQueryData`'s new argument is optional and trailing — existing three-argument
  calls are unaffected and still stamp `Date.now()`.
- `removed.reason` is a **new field on an existing event**, not a new event.
  Structural consumers (the react re-exports, devtools-core's own event mirror)
  keep compiling; a subscriber that ignores `reason` behaves as before. A
  consumer that pattern-matches the `removed` variant exhaustively will now see
  the extra field — additive, never removed.

## Design intent

These are the seams `typewire-sync` and `typewire-offline` build on, and only
those seams: the engine gains no knowledge of tabs, channels, or networks. A sync
adapter registers a `gate` for single-flight and write-locks, reads `reason` to
decide what to broadcast, and uses `resolveSource` + `setQueryData({ updatedAt })`
to apply an inbound mirror. Keeping the surface this thin is what lets those
packages subscribe instead of fork.

## Future (not in this release)

- The sync-side family changes (`typesocket` leader election, a devtools `tab`
  axis, the CLI `init` question) land with the sync package itself.
